Questão 01)

Enunciado:
Prove que, se G é um grafo simples não-direcionado, então a soma dos graus de todos os vértices é par.

Ideia principal:
Em um grafo não-direcionado, cada aresta liga dois vértices. Portanto, quando somamos os graus de todos os vértices, cada aresta é contada duas vezes: uma vez em cada extremidade. Assim, a soma total dos graus é igual a 2 vezes o número de arestas, logo é um número par.

Pseudocódigo:

Algoritmo SomaGrausPar(G)
Entrada: um grafo simples não-direcionado G = (V, E)
Saída: verdadeiro se a soma dos graus dos vértices for par

início
    soma <- 0

    para cada vértice v pertencente a V faça
        soma <- soma + grau(v)
    fim-para

    se soma mod 2 = 0 então
        retorne verdadeiro
    senão
        retorne falso
    fim-se
fim

Passo a passo para resolver:

1. Considere o grafo G = (V, E), em que V é o conjunto de vértices e E é o conjunto de arestas.
2. Para cada vértice v pertencente a V, calcule o grau de v, isto é, a quantidade de arestas incidentes em v.
3. Some todos os graus dos vértices.
4. Observe que cada aresta {u, v} pertencente a E contribui com 1 no grau de u e com 1 no grau de v.
5. Logo, cada aresta contribui com 2 unidades na soma total dos graus.
6. Assim, a soma dos graus de todos os vértices é igual a 2|E|.
7. Como 2|E| é múltiplo de 2, essa soma é par.

Prova matemática:

Seja G = (V, E) um grafo simples não-direcionado.

Para todo e pertencente a E, existe u, v pertencentes a V tal que e = {u, v}.

Como G é não-direcionado:

∀ e = {u, v} ∈ E, e incide em u ∧ e incide em v

Logo:

∀ e = {u, v} ∈ E, e contribui com 1 em grau(u) ∧ e contribui com 1 em grau(v)

Portanto, cada aresta contribui com 2 na soma dos graus:

∀ e ∈ E, contribuição(e) = 2

Assim:

∑ grau(v), para todo v ∈ V = 2 · |E|

Como |E| ∈ N, temos:

|E| ∈ N ⇒ 2 · |E| é par

Logo:

∑ grau(v), para todo v ∈ V = 2 · |E| ⇒ ∑ grau(v) é par

Conclusão:
A soma dos graus de todos os vértices de um grafo simples não-direcionado sempre é par.


Questão 02)

Enunciado:
Mostre que o número de vértices de grau ímpar de um grafo G não-direcionado é sempre par.

Ideia principal:
Pela Questão 01, sabemos que a soma dos graus de todos os vértices de um grafo não-direcionado é par. Os vértices de grau par contribuem com valores pares para essa soma. Portanto, a paridade da soma depende apenas dos vértices de grau ímpar. Como a soma total é par, a quantidade de vértices com grau ímpar também deve ser par.

Pseudocódigo:

Algoritmo QuantidadeGrausImparesPar(G)
Entrada: um grafo não-direcionado G = (V, E)
Saída: verdadeiro se a quantidade de vértices de grau ímpar for par

início
    qtdImpares <- 0

    para cada vértice v pertencente a V faça
        se grau(v) mod 2 = 1 então
            qtdImpares <- qtdImpares + 1
        fim-se
    fim-para

    se qtdImpares mod 2 = 0 então
        retorne verdadeiro
    senão
        retorne falso
    fim-se
fim

Passo a passo para resolver:

1. Considere o grafo G = (V, E), em que V é o conjunto de vértices e E é o conjunto de arestas.
2. Separe os vértices de V em dois conjuntos: os vértices de grau par e os vértices de grau ímpar.
3. Chame de P o conjunto dos vértices de grau par.
4. Chame de I o conjunto dos vértices de grau ímpar.
5. Pela Questão 01, a soma dos graus de todos os vértices é par.
6. A soma dos graus dos vértices de P também é par, pois é uma soma de números pares.
7. Então a soma dos graus dos vértices de I também precisa ser par.
8. Como cada vértice de I possui grau ímpar, a soma desses graus só será par se a quantidade de vértices em I for par.
9. Logo, o número de vértices de grau ímpar é sempre par.

Prova matemática:

Seja G = (V, E) um grafo não-direcionado.

Definimos:

P = {v ∈ V | grau(v) é par}

I = {v ∈ V | grau(v) é ímpar}

Assim:

V = P ∪ I ∧ P ∩ I = ∅

Pela Questão 01:

∑ grau(v), para todo v ∈ V = 2 · |E|

Como |E| ∈ N, temos:

2 · |E| é par

Logo:

∑ grau(v), para todo v ∈ V é par

Podemos separar a soma:

∑ grau(v), para todo v ∈ V =
∑ grau(v), para todo v ∈ P + ∑ grau(v), para todo v ∈ I

Como:

∀ v ∈ P, grau(v) é par

Então:

∑ grau(v), para todo v ∈ P é par

Como a soma total é par e a soma dos graus dos vértices de P é par:

∑ grau(v), para todo v ∈ V é par ∧ ∑ grau(v), para todo v ∈ P é par
⇒ ∑ grau(v), para todo v ∈ I é par

Agora, para todo v ∈ I:

∀ v ∈ I, grau(v) é ímpar

A soma de números ímpares é par se e somente se, a quantidade dé parcelas ímpares for par:

∀ v ∈ I, grau(v) é ímpar ∧ ∑ grau(v), para todo v ∈ I é par
⇒ |I| é par

Conclusão:
Como I representa o conjunto dos vértices de grau ímpar, concluímos que o número de vértices de grau ímpar em um grafo não-direcionado sempre é par.


Questão 03)

Enunciado:
Projete um algoritmo para encontrar o número de componentes conexos de um grafo não-direcionado.

Ideia principal:
Uma componente conexa é um conjunto de vértices em que todos conseguem alcançar uns aos outros por algum caminho. 
Para encontrar o número de componentes conexos, percorremos todos os vértices do grafo. 
Sempre que encontramos um vértice ainda não visitado, iniciamos uma busca em profundidade (DFS) a partir dele. Essa DFS visita todos os vértices da mesma componente conexa. 
Cada vez que precisamos iniciar uma nova DFS, encontramos uma nova componente.

Pseudocódigo:

Algoritmo NumeroComponentesConexos(G)
Entrada: um grafo não-direcionado G = (V, E)
Saída: quantidade de componentes conexos de G

início
    para cada vértice v pertencente a V faça
        visitado[v] <- falso
    fim-para

    componentes <- 0

    para cada vértice v pertencente a V faça
        se visitado[v] = falso então
            componentes <- componentes + 1
            DFS(G, v, visitado)
        fim-se
    fim-para

    retorne componentes
fim

Procedimento DFS(G, v, visitado)
início
    visitado[v] <- verdadeiro

    para cada vértice u adjacente a v faça
        se visitado[u] = falso então
            DFS(G, u, visitado)
        fim-se
    fim-para
fim

Passo a passo para resolver:

1. Considere o grafo G = (V, E), em que V é o conjunto de vértices e E é o conjunto de arestas.
2. Marque todos os vértices como não visitados.
3. Crie uma variavel componentes com valor inicial 0.
4. Percorra todos os vértices do grafo.
5. Se o vértice atual ainda não foi visitado, significa que ele pertence a uma componente conexa que ainda não foi contada.
6. Some 1 na variavel componentes.
7. Execute uma DFS a partir desse vértice.
8. A DFS marcará como visitados todos os vértices que pertencem a essa mesma componente conexa.
9. Continue percorrendo os vértices restantes.
10. No final, o valor de componentes será exatamente o número de componentes conexos do grafo.

Prova matemática:

Seja G = (V, E) um grafo não-direcionado.

Definimos a relação de alcance entre vértices:

u ~ v ⇔ existe um caminho entre u e v em G

Como G é não-direcionado, a relação ~ separa V em classes de equivalencia, chamadas componentes conexas:

C1, C2, ..., Ck

tal que:

V = C1 ∪ C2 ∪ ... ∪ Ck

e:

∀ i, j ∈ {1, 2, ..., k}, i ≠ j ⇒ Ci ∩ Cj = ∅

Além disso:

∀ i ∈ {1, 2, ..., k}, ∀ u, v ∈ Ci ⇒ existe caminho entre u e v

e:

∀ i, j ∈ {1, 2, ..., k}, i ≠ j ∧ u ∈ Ci ∧ v ∈ Cj ⇒ não existe caminho entre u e v

Quando o algoritmo encontra um vértice v ainda não visitado, temos:

v ∈ Ci ∧ visitado[v] = falso ⇒ a componente Ci ainda não foi contada

Ao executar DFS(G, v), todos os vértices alcançáveis a partir de v são visitados:

∀ u ∈ V, existe caminho entre v e u ⇒ visitado[u] = verdadeiro

Como v ∈ Ci, então todos os vértices de Ci são alcançáveis a partir de v:

∀ u ∈ Ci, existe caminho entre v e u ⇒ visitado[u] = verdadeiro

E nenhum vértice fora de Ci é visitado por essa DFS:

∀ u ∈ V, u ∉ Ci ⇒ não existe caminho entre v e u ⇒ u não é visitado pela DFS iniciada em v

Logo, cada execução da DFS correspondé exatamente a uma componente conexa:

DFS iniciada em v ∈ Ci ⇒ conta exatamente Ci

Como o algoritmo percorre todos os vértices:

∀ Ci, existe v ∈ Ci

Se Ci ainda não foi contada, então algum v ∈ Ci estará não visitado quando for analisado:

∃ v ∈ Ci, visitado[v] = falso ⇒ componentes <- componentes + 1

Portanto:

componentes = k

Conclusão:
O algoritmo conta uma vez cada componente conexa do grafo é não conta nenhuma componente mais de uma vez. 
Portanto, ele retorna corretamente o número de componentes conexos de G.


Questão 04)

Enunciado:
Seja G = (V, E) um grafo não-direcionado simples conexo tal que |V| >= 2. Mostre que há, pelo menos, dois vértices que possuem o mesmo grau.

Ideia principal:
Se o grafo é simples, não-direcionado e possui n vértices, então o grau de qualquer vértice está entre 0 e n - 1. Porém, como o grafo é conexo e n >= 2, nenhum vértice pode ter grau 0. Logo, os graus possíveis são apenas 1, 2, 3, ..., n - 1. Existem n vértices, mas apenas n - 1 valores possíveis de grau. Pelo princípio das gavetas, pelo menos dois vértices devem ter o mesmo grau.

Pseudocódigo:

Algoritmo ExisteDoisVerticesMesmoGrau(G)
Entrada: um grafo simples não-direcionado conexo G = (V, E), com |V| >= 2
Saída: dois vértices que possuem o mesmo grau

início
    para cada vértice v pertencente a V faça
        grauV <- grau(v)

        se tabela[grauV] existe então
            retorne tabela[grauV], v
        senão
            tabela[grauV] <- v
        fim-se
    fim-para
fim

Passo a passo para resolver:

1. Considere o grafo G = (V, E), com |V| = n e n >= 2.
2. Como G é simples, um vértice pode estar ligado no máximo aos outros n - 1 vértices.
3. Assim, para todo vértice v pertencente a V, grau(v) <= n - 1.
4. Como G é conexo e n >= 2, nenhum vértice pode estar isolado.
5. Assim, para todo vértice v pertencente a V, grau(v) >= 1.
6. Portanto, os graus possíveis são 1, 2, 3, ..., n - 1.
7. Existem n vértices no grafo.
8. Existem apenas n - 1 valores possíveis de grau.
9. Pelo princípio das gavetas, se n vértices recebem apenas n - 1 valores possíveis de grau, então pelo menos dois vértices recebem o mesmo valor.
10. Logo, existem pelo menos dois vértices em G que possuem o mesmo grau.

Prova matemática:

Seja G = (V, E) um grafo simples não-direcionado conexo.

Seja:

|V| = n, com n >= 2

Como G é simples, um vértice não possui laço e não possui arestas repetidas. Então, cada vértice pode se ligar no máximo aos outros n - 1 vértices:

∀ v ∈ V, grau(v) <= n - 1

Como G é conexo e n >= 2, não pode existir vértice isolado:

∀ v ∈ V, grau(v) >= 1

Logo:

∀ v ∈ V, grau(v) ∈ {1, 2, 3, ..., n - 1}

Definimos a função:

f: V -> {1, 2, 3, ..., n - 1}

tal que:

∀ v ∈ V, f(v) = grau(v)

Temos:

|V| = n

e:

|{1, 2, 3, ..., n - 1}| = n - 1

Assim:

|V| > |{1, 2, 3, ..., n - 1}|

Pelo princípio das gavetas:

|V| > |{1, 2, 3, ..., n - 1}| ⇒ ∃ u, v ∈ V, u ≠ v ∧ f(u) = f(v)

Como f(x) = grau(x), temos:

∃ u, v ∈ V, u ≠ v ∧ grau(u) = grau(v)

Conclusão:
Portanto, em todo grafo simples não-direcionado conexo com |V| >= 2, existem pelo menos dois vértices que possuem o mesmo grau.


Questão 05)

Enunciado:
Seja G = (V, E) um grafo não-direcionado completo. Encontre o número de subgrafos que podem ser encontrados em G.

Ideia principal:
Se G é um grafo completo com n vértices, então todo par de vértices possui uma aresta. Para formar um subgrafo, primeiro escolhemos um subconjunto de vértices. Se esse subconjunto possui k vértices, então existem C(k, 2) arestas possíveis entre eles. Como um subgrafo pode conter qualquer subconjunto dessas arestas, existem 2^(C(k, 2)) formas de escolher as arestas. Como existem C(n, k) formas de escolher k vértices, o total de subgrafos é a soma desses valores para k indo de 0 até n.

Pseudocódigo:

Algoritmo NumeroSubgrafosGrafoCompleto(G)
Entrada: um grafo completo não-direcionado G = (V, E)
Saída: número de subgrafos de G

início
    n <- |V|
    total <- 0

    para k <- 0 até n faça
        qtdVertices <- combinacao(n, k)
        qtdArestasPossiveis <- k * (k - 1) / 2
        qtdSubgrafosComKVertices <- qtdVertices * 2^qtdArestasPossiveis
        total <- total + qtdSubgrafosComKVertices
    fim-para

    retorne total
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo completo não-direcionado.
2. Seja n = |V|, isto é, n é o número de vértices de G.
3. Como G é completo, todo par de vértices distintos possui uma aresta.
4. Para montar um subgrafo, primeiro escolhemos quantos vértices ele terá. Chame essa quantidade de k.
5. Existem C(n, k) formas de escolher k vértices entre os n vértices de G.
6. Depois de escolher esses k vértices, existem C(k, 2) arestas possíveis entre eles.
7. Cada uma dessas arestas pode aparecer ou não aparecer no subgrafo.
8. Portanto, para k vértices escolhidos, existem 2^(C(k, 2)) formas de escolher as arestas.
9. Assim, para cada k, existem C(n, k) · 2^(C(k, 2)) subgrafos com k vértices.
10. Para obter o número total de subgrafos, somamos esse valor para todo k de 0 até n.

Prova matemática:

Seja G = (V, E) um grafo completo não-direcionado.

Seja:

|V| = n

Como G é completo:

∀ u, v ∈ V, u ≠ v ⇒ {u, v} ∈ E

Um subgrafo H de G pode ser escrito como:

H = (V', E')

tal que:

V' ⊆ V

e:

E' ⊆ {{u, v} | u, v ∈ V' ∧ u ≠ v}

Para todo V' ⊆ V, se |V'| = k, então o número de arestas possíveis em V' e:

|{{u, v} | u, v ∈ V' ∧ u ≠ v}| = C(k, 2)

Como cada aresta pode pertencer ou não pertencer a E':

∀ e ∈ {{u, v} | u, v ∈ V' ∧ u ≠ v}, e ∈ E' ∨ e ∉ E'

Logo, para um conjunto V' com k vértices:

número de escolhas para E' = 2^(C(k, 2))

Como existem C(n, k) formas de escolher V' com k vértices:

número de subgrafos com k vértices = C(n, k) · 2^(C(k, 2))

Portanto, o número total de subgrafos de G é:

∑ C(n, k) · 2^(C(k, 2)), para todo k ∈ {0, 1, 2, ..., n}

Ou seja:

Total = ∑(k = 0 até n) C(n, k) · 2^(k(k - 1)/2)

Conclusão:
Se G é um grafo completo não-direcionado com n vértices, então o número total de subgrafos de G é:

Total = ∑(k = 0 até n) C(n, k) · 2^(k(k - 1)/2)


Questão 06)

Enunciado:
Seja G = (V, E) um grafo direcionado. Seja u pertencente a V um vértice qualquer do grafo. Projete um algoritmo para encontrar todos os vértices que podem ser atingidos a partir de u.

Ideia principal:
Para encontrar todos os vértices atingíveis a partir de u, basta iniciar uma busca em profundidade (DFS) em u e seguir apenas as arestas no sentido correto. Sempre que existir uma aresta direcionada (v, w), saindo de v e chegando em w, a busca pode ir de v para w. Ao final, todos os vértices marcados como visitados são exatamente os vértices que podem ser atingidos a partir de u.

Pseudocódigo:

Algoritmo VerticesAtingiveis(G, u)
Entrada: um grafo direcionado G = (V, E) e um vértice u pertencente a V
Saída: conjunto de vértices atingíveis a partir de u

início
    para cada vértice v pertencente a V faça
        visitado[v] <- falso
    fim-para

    DFS_Direcionada(G, u, visitado)

    atingíveis <- conjunto vazio

    para cada vértice v pertencente a V faça
        se visitado[v] = verdadeiro então
            adicione v em atingíveis
        fim-se
    fim-para

    retorne atingíveis
fim

Procedimento DFS_Direcionada(G, v, visitado)
início
    visitado[v] <- verdadeiro

    para cada aresta (v, w) pertencente a E faça
        se visitado[w] = falso então
            DFS_Direcionada(G, w, visitado)
        fim-se
    fim-para
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Escolha o vértice inicial u pertencente a V.
3. Marque todos os vértices como não visitados.
4. Inicie uma DFS a partir de u.
5. Durante a DFS, siga apenas as arestas que saem do vértice atual.
6. Se existe uma aresta direcionada (v, w), então a busca pode ir de v para w.
7. Sempre que um novo vértice for encontrado, marque-o como visitado.
8. Continue a busca até não existir mais nenhum vértice novo que possa ser alcançado.
9. Ao final, todos os vértices marcados como visitados formam o conjunto dos vértices atingíveis a partir de u.
10. Retorne esse conjunto.

Prova matemática:

Seja G = (V, E) um grafo direcionado é seja u ∈ V.

Definimos o conjunto dos vértices atingíveis a partir de u:

R(u) = {v ∈ V | existe um caminho direcionado de u até v}

Queremos provar que o algoritmo retorna exatamente R(u).

Primeiro, mostramos que todo vértice visitado pelo algoritmo pertence a R(u).

No início:

visitado[u] = verdadeiro

Como existe um caminho de tamanho 0 de u até u:

u ∈ R(u)

Durante a DFS, se o algoritmo visita w a partir de v, então existe uma aresta direcionada (v, w) ∈ E.

Se v ∈ R(u) ∧ (v, w) ∈ E, então existe caminho direcionado de u até v e uma aresta de v até w.

Logo:

v ∈ R(u) ∧ (v, w) ∈ E ⇒ w ∈ R(u)

Portanto:

∀ w ∈ V, visitado[w] = verdadeiro ⇒ w ∈ R(u)

Agora, mostramos que todo vértice pertencente a R(u) será visitado pelo algoritmo.

Se x ∈ R(u), então existe um caminho direcionado de u até x:

u = v0, v1, v2, ..., vk = x

tal que:

∀ i ∈ {0, 1, ..., k - 1}, (vi, vi+1) ∈ E

Como a DFS começa em u:

visitado[v0] = verdadeiro

Se visitado[vi] = verdadeiro e (vi, vi+1) ∈ E, então a DFS analisa a aresta que sai de vi e chega em vi+1.

Logo:

visitado[vi] = verdadeiro ∧ (vi, vi+1) ∈ E ⇒ visitado[vi+1] = verdadeiro

Por repeticao desse argumento em todo o caminho:

∀ i ∈ {0, 1, ..., k}, visitado[vi] = verdadeiro

Como vk = x:

x ∈ R(u) ⇒ visitado[x] = verdadeiro

Assim:

∀ x ∈ V, x ∈ R(u) ⇒ visitado[x] = verdadeiro

Juntando as duas partes:

∀ x ∈ V, visitado[x] = verdadeiro ⇔ x ∈ R(u)

Conclusão:
O algoritmo retorna exatamente o conjunto dos vértices que podem ser atingidos a partir de u, pois um vértice é visitado se e somente se, existe um caminho direcionado de u até ele.


Questão 07)

Enunciado:
Seja G = (V, E) um grafo direcionado. Seja u pertencente a V um vértice qualquer do grafo. Implemente um algoritmo para encontrar todos os vértices que podem ser atingidos a partir de u.

Ideia principal:
Para implementar a solução, podemos representar o grafo por lista de adjacência. Em um grafo direcionado, a lista de adjacência de um vértice v contém apenas os vértices w tais que existe uma aresta saindo de v e chegando em w, isto é, (v, w) pertencente a E. Assim, basta iniciar uma DFS em u e seguir somente essas arestas de saída. Todos os vértices visitados pela DFS são os vértices atingíveis a partir de u.

Pseudocódigo:

Algoritmo EncontrarAtingiveis(G, u)
Entrada: grafo direcionado G = (V, E), representado por lista de adjacência, e um vértice u pertencente a V
Saída: lista com todos os vértices atingíveis a partir de u

início
    para cada vértice v pertencente a V faça
        visitado[v] <- falso
    fim-para

    resultado <- lista vazia

    Buscar(G, u, visitado, resultado)

    retorne resultado
fim

Procedimento Buscar(G, v, visitado, resultado)
início
    visitado[v] <- verdadeiro
    adicione v em resultado

    para cada vértice w pertencente a Adj[v] faça
        se visitado[w] = falso então
            Buscar(G, w, visitado, resultado)
        fim-se
    fim-para
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Represente G usando lista de adjacência.
3. Para cada vértice v, Adj[v] deve conter apenas os vértices w para os quais existe a aresta direcionada (v, w).
4. Escolha o vértice inicial u pertencente a V.
5. Marque todos os vértices como não visitados.
6. Crie uma lista vazia chamada resultado.
7. Execute a busca a partir de u.
8. Ao visitar um vértice v, marque v como visitado e adicione v em resultado.
9. Para cada w pertencente a Adj[v], se w ainda não foi visitado, continue a busca a partir de w.
10. Quando a busca terminar, resultado contém exatamente todos os vértices atingíveis a partir de u.

Prova matemática:

Seja G = (V, E) um grafo direcionado é seja u ∈ V.

Pela representacao por lista de adjacência:

∀ v, w ∈ V, w ∈ Adj[v] ⇔ (v, w) ∈ E

Definimos o conjunto dos vértices atingíveis a partir de u:

A(u) = {x ∈ V | existe caminho direcionado de u até x}

O algoritmo retorna o conjunto:

R = {x ∈ V | visitado[x] = verdadeiro}

Queremos provar que:

R = A(u)

Primeiro, provamos que R ⊆ A(u).

O primeiro vértice visitado é u:

visitado[u] = verdadeiro

Como existe caminho de tamanho 0 de u até u:

u ∈ A(u)

Durante a busca, um vértice w só é visitado a partir de algum vértice v já visitado, quando w ∈ Adj[v].

Pela definição da lista de adjacência:

w ∈ Adj[v] ⇒ (v, w) ∈ E

Se v ∈ A(u) e (v, w) ∈ E, então existe caminho direcionado de u até v e uma aresta de v até w.

Logo:

v ∈ A(u) ∧ (v, w) ∈ E ⇒ w ∈ A(u)

Portanto:

∀ x ∈ V, x ∈ R ⇒ x ∈ A(u)

Agora, provamos que A(u) ⊆ R.

Se x ∈ A(u), então existe um caminho direcionado:

u = v0, v1, v2, ..., vk = x

tal que:

∀ i ∈ {0, 1, ..., k - 1}, (vi, vi+1) ∈ E

Pela lista de adjacência:

∀ i ∈ {0, 1, ..., k - 1}, (vi, vi+1) ∈ E ⇒ vi+1 ∈ Adj[vi]

Como a busca começa em u:

visitado[v0] = verdadeiro

Se visitado[vi] = verdadeiro e vi+1 ∈ Adj[vi], então o algoritmo analisa vi+1 na lista Adj[vi].

Assim:

visitado[vi] = verdadeiro ∧ vi+1 ∈ Adj[vi] ⇒ visitado[vi+1] = verdadeiro

Aplicando isso para todo o caminho:

∀ i ∈ {0, 1, ..., k}, visitado[vi] = verdadeiro

Como vk = x:

x ∈ A(u) ⇒ x ∈ R

Portanto:

∀ x ∈ V, x ∈ A(u) ⇒ x ∈ R

Juntando os dois resultados:

∀ x ∈ V, x ∈ R ⇔ x ∈ A(u)

Logo:

R = A(u)

Conclusão:
O algoritmo implementado com lista de adjacência e DFS retorna exatamente todos os vértices que podem ser atingidos a partir de u, pois ele visita um vértice se e somente se, existe um caminho direcionado de u até esse vértice.


Questão 08)

Enunciado:
Seja G = (V, E) um grafo direcionado. Projete uma solução para dizer se há um ciclo em G.

Ideia principal:
Para descobrir se existe ciclo em um grafo direcionado, usamos uma DFS com três estados para os vértices: não visitado, em processamento e finalizado. Um vértice em processamento é um vértice que já foi visitado, mas cuja DFS ainda não terminou. Se durante a DFS encontramos uma aresta para um vértice que ainda está em processamento, então encontramos um ciclo.

Pseudocódigo:

Algoritmo ExisteCicloDirecionado(G)
Entrada: um grafo direcionado G = (V, E)
Saída: verdadeiro se G possui ciclo, falso caso contrário

início
    para cada vértice v pertencente a V faça
        estado[v] <- nao_visitado
    fim-para

    para cada vértice v pertencente a V faça
        se estado[v] = nao_visitado então
            se DFS_Ciclo(G, v, estado) = verdadeiro então
                retorne verdadeiro
            fim-se
        fim-se
    fim-para

    retorne falso
fim

Procedimento DFS_Ciclo(G, v, estado)
início
    estado[v] <- em_processamento

    para cada aresta (v, w) pertencente a E faça
        se estado[w] = em_processamento então
            retorne verdadeiro
        fim-se

        se estado[w] = nao_visitado então
            se DFS_Ciclo(G, w, estado) = verdadeiro então
                retorne verdadeiro
            fim-se
        fim-se
    fim-para

    estado[v] <- finalizado
    retorne falso
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Inicialmente, marque todos os vértices como não visitados.
3. Percorra todos os vértices do grafo.
4. Sempre que encontrar um vértice não visitado, inicie uma DFS a partir dele.
5. Ao entrar em um vértice v na DFS, marque v como em processamento.
6. Analise todas as arestas que saem de v.
7. Se existir uma aresta (v, w) e w estiver em processamento, então existe um caminho de w até v na pilha da DFS e uma aresta de v para w, formando um ciclo.
8. Se w não foi visitado, continue a DFS a partir de w.
9. Quando terminar de analisar todas as arestas que saem de v, marque v como finalizado.
10. Se nenhuma aresta para vértice em processamento for encontrada, então o grafo não possui ciclo.

Prova matemática:

Seja G = (V, E) um grafo direcionado.

Durante a DFS, definimos:

estado[v] = em_processamento ⇔ v pertence a pilha atual da recursão

Ou seja:

∀ v ∈ V, estado[v] = em_processamento ⇒ existe caminho direcionado do primeiro vértice da DFS até v na pilha

Primeiro, mostramos que se o algoritmo retorna verdadeiro, então G possui ciclo.

O algoritmo retorna verdadeiro quando encontra uma aresta:

(v, w) ∈ E

tal que:

estado[w] = em_processamento

Como w está em processamento, w está na pilha da DFS antes de v. Logo, existe um caminho direcionado de w até v:

estado[w] = em_processamento ∧ estado[v] = em_processamento ⇒ existe caminho direcionado de w até v

Como também existe a aresta (v, w):

existe caminho de w até v ∧ (v, w) ∈ E ⇒ existe ciclo

Portanto:

∀ v, w ∈ V, estado[w] = em_processamento ∧ (v, w) ∈ E ⇒ G possui ciclo

Agora, mostramos que se G possui ciclo, então o algoritmo retorna verdadeiro.

Suponha que exista um ciclo direcionado em G:

C = v0, v1, v2, ..., vk, v0

tal que:

∀ i ∈ {0, 1, ..., k - 1}, (vi, vi+1) ∈ E

e:

(vk, v0) ∈ E

Como o algoritmo percorre todos os vértices:

∀ v ∈ V, v será analisado pela DFS ou já terá sido visitado

Considere o primeiro vértice do ciclo C que for visitado pela DFS. Chame esse vértice de vi.

Como as arestas do ciclo seguem o sentido:

vi -> vi+1 -> ... -> vk -> v0 -> ... -> vi

a DFS pode seguir os vértices do ciclo enquanto eles ainda não estiverem finalizados.

Antes de finalizar vi, a DFS encontra uma aresta que aponta para algum vértice do ciclo que ainda está em processamento.

Assim:

∃ x, y ∈ V, (x, y) ∈ E ∧ estado[y] = em_processamento

Logo, o algoritmo retorna verdadeiro.

Portanto:

G possui ciclo ⇒ algoritmo retorna verdadeiro

Juntando os dois resultados:

algoritmo retorna verdadeiro ⇔ G possui ciclo

Conclusão:
O algoritmo detecta corretamente se há ciclo em um grafo direcionado, pois retorna verdadeiro se e somente se, encontra uma aresta para um vértice que ainda está em processamento na DFS, o que caracteriza um ciclo direcionado.


Questão 09)

Enunciado:
Use a ordem alfabética para tratar empates. Classifique as arestas. Para cada vértice, crie dois tempos que marquem o início da visita e o fim da visita.

Ideia principal:
Para resolver essa questão, usamos uma busca em profundidade (DFS). A ordem alfabética é usada sempre que houver escolha entre vértices: primeiro ordenamos os vértices alfabéticamente e também ordenamos alfabéticamente a lista de adjacência de cada vértice. Durante a DFS, cada vértice recebe um tempo de descoberta, quando a visita começa, é um tempo de finalização, quando todos os seus vizinhos já foram analisados. As arestas são classificadas de acordo com o estado do vértice de destino no momento em que a aresta e analisada.

Pseudocódigo:

Algoritmo DFS_ClassificarArestas(G)
Entrada: um grafo direcionado G = (V, E)
Saída: tempo de início, tempo de fim e classificacao das arestas

início
    ordene V em ordem alfabética

    para cada vértice v pertencente a V faça
        ordene Adj[v] em ordem alfabética
        cor[v] <- branco
        pai[v] <- nulo
    fim-para

    tempo <- 0

    para cada vértice v pertencente a V, em ordem alfabética, faça
        se cor[v] = branco então
            DFS_Visita(G, v)
        fim-se
    fim-para
fim

Procedimento DFS_Visita(G, v)
início
    cor[v] <- cinza
    tempo <- tempo + 1
    início[v] <- tempo

    para cada vértice w pertencente a Adj[v], em ordem alfabética, faça
        se cor[w] = branco então
            classificar (v, w) como aresta de árvore
            pai[w] <- v
            DFS_Visita(G, w)
        senão se cor[w] = cinza então
            classificar (v, w) como aresta de retorno
        senão
            se início[v] < início[w] então
                classificar (v, w) como aresta de avanço
            senão
                classificar (v, w) como aresta de cruzamento
            fim-se
        fim-se
    fim-para

    cor[v] <- preto
    tempo <- tempo + 1
    fim[v] <- tempo
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Ordene todos os vértices de V em ordem alfabética.
3. Para cada vértice v, ordene também sua lista de adjacência Adj[v] em ordem alfabética.
4. Marque todos os vértices inicialmente com a cor branco.
5. Crie uma variavel tempo iniciando em 0.
6. Percorra os vértices em ordem alfabética.
7. Quando encontrar um vértice branco, inicie uma DFS a partir dele.
8. Ao iniciar a visita de um vértice v, marque v como cinza e registre início[v].
9. Para cada aresta (v, w), observe a cor de w.
10. Se w estiver branco, a aresta (v, w) é uma aresta de árvore.
11. Se w estiver cinza, a aresta (v, w) é uma aresta de retorno.
12. Se w estiver preto e início[v] < início[w], a aresta (v, w) é uma aresta de avanço.
13. Se w estiver preto e início[v] > início[w], a aresta (v, w) é uma aresta de cruzamento.
14. Quando todos os vizinhos de v forem analisados, marque v como preto e registre fim[v].
15. Ao final, todos os vértices teráo tempo de início e fim, e todas as arestas teráo uma classificacao.

Prova matemática:

Seja G = (V, E) um grafo direcionado.

Para todo vértice v pertencente a V, a DFS registra dois tempos:

∀ v ∈ V, início[v] ∈ N ∧ fim[v] ∈ N

Como o tempo aumenta ao iniciar e ao finalizar cada vértice:

∀ v ∈ V, início[v] < fim[v]

Durante a DFS, cada vértice possui uma cor:

branco: ainda não foi visitado

cinza: foi iniciado, mas ainda não foi finalizado

preto: já foi finalizado

Assim, no momento em que uma aresta (u, v) ∈ E e analisada, temos exatamente um dos casos:

∀ (u, v) ∈ E, cor[v] = branco ∨ cor[v] = cinza ∨ cor[v] = preto

Caso 1: se cor[v] = branco, então v ainda não foi descoberto. Logo, a DFS descobre v a partir de u:

∀ (u, v) ∈ E, cor[v] = branco ⇒ pai[v] = u

Portanto:

cor[v] = branco ⇒ (u, v) e aresta de árvore

Caso 2: se cor[v] = cinza, então v está na pilha atual da recursão. Logo, existe um caminho de v até u na árvore DFS:

cor[v] = cinza ⇒ existe caminho de v até u na árvore DFS

Como também existe a aresta (u, v):

existe caminho de v até u ∧ (u, v) ∈ E ⇒ (u, v) fecha um ciclo

Portanto:

cor[v] = cinza ⇒ (u, v) e aresta de retorno

Caso 3: se cor[v] = preto e início[u] < início[v], então v foi descoberto depois de u e já foi finalizado. Nesse caso, v e descendente de u na árvore DFS:

cor[v] = preto ∧ início[u] < início[v] ⇒ v e descendente de u

Portanto:

cor[v] = preto ∧ início[u] < início[v] ⇒ (u, v) e aresta de avanço

Caso 4: se cor[v] = preto e início[u] > início[v], então v foi descoberto antes de u e já foi finalizado. Nesse caso, a aresta liga vértices que não estão na mesma relação direta de descendencia de u para v:

cor[v] = preto ∧ início[u] > início[v] ⇒ v não e descendente de u

Portanto:

cor[v] = preto ∧ início[u] > início[v] ⇒ (u, v) e aresta de cruzamento

Como cada aresta (u, v) ∈ E cai em exatamente um desses casos, todas as arestas são classificadas corretamente:

∀ (u, v) ∈ E, (u, v) pertence a exatamente uma classe

A ordem alfabética garante que os empates sejam tratados sempre da mesma forma:

∀ a, b ∈ V, a < b alfabéticamente ⇒ a e analisado antes de b

Conclusão:
O algoritmo executa uma DFS em ordem alfabética, registra corretamente início[v] e fim[v] para todo v pertencente a V, e classifica cada aresta de G como árvore, retorno, avanço ou cruzamento de acordo com os tempos e estados da DFS.


Questão 10)

Enunciado:
Projete uma solução para encontrar o menor caminho entre dois vértices quaisquer.

Ideia principal:
Como o enunciado não informa pesos nas arestas, consideramos que todas as arestas possuem o mesmo custo. Nesse caso, o menor caminho entre dois vértices é o caminho com a menor quantidade de arestas. Para encontrar esse caminho, usamos a busca em largura (BFS), pois ela visita primeiro os vértices que estão a distância 1, depois distância 2, depois distância 3, e assim por diante. Quando o vértice destino é encontrado, a distância registrada é mínima.

Pseudocódigo:

Algoritmo MenorCaminho(G, origem, destino)
Entrada: um grafo G = (V, E), um vértice origem pertencente a V e um vértice destino pertencente a V
Saída: menor caminho entre origem e destino, ou informa que não existe caminho

início
    para cada vértice v pertencente a V faça
        visitado[v] <- falso
        distância[v] <- infinito
        pai[v] <- nulo
    fim-para

    visitado[origem] <- verdadeiro
    distância[origem] <- 0
    fila <- fila vazia
    enfileire origem em fila

    enquanto fila não estiver vazia faça
        v <- desenfileire fila

        para cada vértice w adjacente a v faça
            se visitado[w] = falso então
                visitado[w] <- verdadeiro
                distância[w] <- distância[v] + 1
                pai[w] <- v
                enfileire w em fila
            fim-se
        fim-para
    fim-enquanto

    se visitado[destino] = falso então
        retorne "não existe caminho"
    fim-se

    caminho <- lista vazia
    atual <- destino

    enquanto atual != nulo faça
        adicione atual no início de caminho
        atual <- pai[atual]
    fim-enquanto

    retorne caminho
fim

Passo a passo para resolver:

1. Considere G = (V, E), com origem e destino pertencentes a V.
2. Marque todos os vértices como não visitados.
3. Defina a distância de todos os vértices como infinito.
4. Defina pai[v] como nulo para todos os vértices.
5. Marque a origem como visitada e coloque distância[origem] = 0.
6. Coloque a origem em uma fila.
7. Enquanto a fila não estiver vazia, remova o primeiro vértice da fila.
8. Para cada vizinho ainda não visitado, marque-o como visitado.
9. A distância do vizinho será a distância do vértice atual mais 1.
10. Guarde o vértice atual como pai do vizinho.
11. Coloque o vizinho na fila.
12. Ao final da BFS, se o destino não foi visitado, não existe caminho.
13. Se o destino foi visitado, use o vetor pai para reconstruir o caminho de tras para frente.
14. O caminho reconstruido será o menor caminho entre origem e destino.

Prova matemática:

Seja G = (V, E) um grafo não ponderado.

Sejam:

s ∈ V, o vértice de origem

t ∈ V, o vértice de destino

Definimos a distância mínima entre s e v como:

δ(s, v) = menor número de arestas em um caminho de s até v

Se não existir caminho de s até v, então:

δ(s, v) = infinito

A BFS define:

distância[s] = 0

e, sempre que visita w a partir de v:

distância[w] = distância[v] + 1

Primeiro, mostramos que toda distância calculada corresponde a algum caminho real.

Se distância[w] = distância[v] + 1 e (v, w) ∈ E, então existe um caminho de s até v seguido da aresta (v, w).

Logo:

∀ v, w ∈ V, (v, w) ∈ E ∧ distância[v] = k ⇒ distância[w] = k + 1

Portanto:

∀ x ∈ V, distância[x] = k ⇒ existe caminho de s até x com k arestas

Agora, mostramos que a BFS não deixa de encontrar um caminho menor.

A BFS usa uma fila. Assim, todos os vértices com distância k são processados antes dos vértices com distância k + 1:

∀ x, y ∈ V, distância[x] < distância[y] ⇒ x e processado antes de y

Suponha, por contradicao, que exista um caminho menor até algum vértice x do que o valor encontrado pela BFS:

δ(s, x) < distância[x]

Se δ(s, x) = k, então existe um caminho:

s = v0, v1, v2, ..., vk = x

tal que:

∀ i ∈ {0, 1, ..., k - 1}, (vi, vi+1) ∈ E

Pela ordem da BFS:

distância[v0] = 0

e:

∀ i ∈ {0, 1, ..., k - 1}, distância[vi+1] <= distância[vi] + 1

Logo:

distância[x] <= k

Como k = δ(s, x), temos:

distância[x] <= δ(s, x)

Mas toda distância da BFS corresponde a um caminho real, então:

δ(s, x) <= distância[x]

Portanto:

distância[x] = δ(s, x)

Assim:

∀ x ∈ V, visitado[x] = verdadeiro ⇒ distância[x] = δ(s, x)

Para o destino t:

t ∈ V ∧ visitado[t] = verdadeiro ⇒ distância[t] = δ(s, t)

Como pai[w] guarda o vértice anterior usado para descobrir w:

∀ w ∈ V, pai[w] = v ⇒ (v, w) ∈ E

Logo, seguir os pais de t até s reconstrui um caminho real de tamanho distância[t]:

pai reconstrui caminho de s até t ⇒ tamanho do caminho = distância[t] = δ(s, t)

Conclusão:
O algoritmo encontra corretamente o menor caminho entre origem e destino, pois a BFS calcula a menor distância em número de arestas e o vetor pai permite reconstruir esse caminho mínimo.


Questão 11)

Enunciado:
Seja G = (V, E) um grafo direcionado. Projete uma solução para encontrar um conjunto de vértices cujo fecho transitivo direto seja V.

Ideia principal:
O fecho transitivo direto de um conjunto S é o conjunto de vértices que podem ser atingidos a partir de algum vértice de S. Como a questão pede apenas um conjunto, e não o menor conjunto, uma solução sempre correta é escolher S = V. Assim, todo vértice do grafo pertence ao conjunto inicial e, portanto, pertence ao seu próprio fecho transitivo direto.

Pseudocódigo:

Algoritmo ConjuntoFechoDiretoTotal(G)
Entrada: um grafo direcionado G = (V, E)
Saída: um conjunto S tal que o fecho transitivo direto de S seja V

início
    S <- conjunto vazio

    para cada vértice v pertencente a V faça
        adicione v em S
    fim-para

    retorne S
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Queremos encontrar um conjunto S de vértices tal que todos os vértices de V sejam atingíveis a partir de S.
3. Como a questão não exige o menor conjunto, podemos escolher todos os vértices do grafo.
4. Defina S = V.
5. Para todo vértice v pertencente a V, temos que v também pertence a S.
6. Todo vértice v e atingível a partir dele mesmo por um caminho de tamanho 0.
7. Logo, todo vértice v pertencente a V pertence ao fecho transitivo direto de S.
8. Portanto, o fecho transitivo direto de S é igual a V.

Prova matemática:

Seja G = (V, E) um grafo direcionado.

Definimos o fecho transitivo direto de um conjunto S como:

F+(S) = {x ∈ V | ∃ s ∈ S tal que existe caminho direcionado de s até x}

Escolhemos:

S = V

Queremos provar que:

F+(S) = V

Primeiro, mostramos que V ⊆ F+(S).

Como S = V:

∀ x ∈ V, x ∈ S

Todo vértice alcanca a si mesmo por um caminho de tamanho 0:

∀ x ∈ V, existe caminho direcionado de x até x

Logo:

∀ x ∈ V, x ∈ S ∧ existe caminho direcionado de x até x ⇒ x ∈ F+(S)

Portanto:

∀ x ∈ V, x ∈ V ⇒ x ∈ F+(S)

Assim:

V ⊆ F+(S)

Agora, mostramos que F+(S) ⊆ V.

Pela definição de fecho transitivo direto:

F+(S) = {x ∈ V | ∃ s ∈ S tal que existe caminho direcionado de s até x}

Todo elemento de F+(S) pertence a V:

∀ x, x ∈ F+(S) ⇒ x ∈ V

Assim:

F+(S) ⊆ V

Como:

V ⊆ F+(S) ∧ F+(S) ⊆ V

Concluimos:

F+(S) = V

Conclusão:
O conjunto S = V sempre possui fecho transitivo direto igual a V. Portanto, o algoritmo retorna corretamente um conjunto de vértices cujo fecho transitivo direto e todo o conjunto de vértices do grafo.


Questão 12)

Enunciado:
Seja G = (V, E) um grafo direcionado. Projete uma solução para encontrar o menor conjunto de vértices cujo fecho transitivo direto seja V.

Ideia principal:
Para encontrar o menor conjunto de vértices cujo fecho transitivo direto seja V, devemos analisar as componentes fortemente conexas do grafo. Dentro de uma componente fortemente conexa, qualquer vértice alcanca todos os outros vértices da mesma componente. Depois, contraimos cada componente fortemente conexa em um único vértice, formando o grafo condensado. Esse grafo condensado é acíclico. Para que todos os vértices sejam atingidos, precisamos escolher pelo menos um vértice de cada componente que não recebe aresta de nenhuma outra componente. Essas componentes são chamadas componentes-fonte. Escolher um vértice de cada componente-fonte gera o menor conjunto possível.

Pseudocódigo:

Algoritmo MenorConjuntoFechoDireto(G)
Entrada: um grafo direcionado G = (V, E)
Saída: menor conjunto S tal que o fecho transitivo direto de S seja V

início
    componentes <- CalcularComponentesFortementeConexas(G)

    para cada componente C pertencente a componentes faça
        entrada[C] <- falso
    fim-para

    para cada aresta (u, v) pertencente a E faça
        Cu <- componente que contém u
        Cv <- componente que contém v

        se Cu != Cv então
            entrada[Cv] <- verdadeiro
        fim-se
    fim-para

    S <- conjunto vazio

    para cada componente C pertencente a componentes faça
        se entrada[C] = falso então
            escolha um vértice x pertencente a C
            adicione x em S
        fim-se
    fim-para

    retorne S
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Encontre todas as componentes fortemente conexas de G.
3. Lembre que, dentro de uma componente fortemente conexa, qualquer vértice alcanca qualquer outro vértice da mesma componente.
4. Contraia cada componente fortemente conexa em um único vértice.
5. O grafo obtido é chamado grafo condensado.
6. Verifique quais componentes do grafo condensado não recebem arestas de outras componentes.
7. Essas componentes são chamadas componentes-fonte.
8. Para cada componente-fonte, escolha exatamente um vértice pertencente a ela.
9. Coloque esses vértices escolhidos no conjunto S.
10. Retorne S.
11. Esse conjunto é mínimo, pois nenhuma componente-fonte pode ser atingida a partir de outra componente.
12. Logo, precisamos escolher pelo menos um vértice de cada componente-fonte.

Prova matemática:

Seja G = (V, E) um grafo direcionado.

Definimos o fecho transitivo direto de S como:

F+(S) = {x ∈ V | ∃ s ∈ S tal que existe caminho direcionado de s até x}

Sejam:

C1, C2, ..., Ck

as componentes fortemente conexas de G.

Para toda componente Ci:

∀ u, v ∈ Ci, existe caminho direcionado de u até v

Construimos o grafo condensado Gc = (Vc, Ec), em que:

Vc = {C1, C2, ..., Ck}

e:

(Ci, Cj) ∈ Ec ⇔ ∃ u ∈ Ci, ∃ v ∈ Cj tal que (u, v) ∈ E ∧ Ci ≠ Cj

No grafo condensado, uma componente-fonte é uma componente que não possui aresta de entrada:

Fonte(Ci) ⇔ não existe Cj ∈ Vc tal que Cj ≠ Ci ∧ (Cj, Ci) ∈ Ec

Seja P o conjunto das componentes-fonte:

P = {Ci ∈ Vc | Fonte(Ci)}

O algoritmo escolhe um vértice de cada componente-fonte:

∀ Ci ∈ P, ∃ s ∈ S tal que s ∈ Ci

Primeiro, mostramos que F+(S) = V.

Como Gc é acíclico, toda componente de Gc é uma componente-fonte ou e atingível a partir de alguma componente-fonte:

∀ Cj ∈ Vc, ∃ Ci ∈ P tal que existe caminho direcionado de Ci até Cj em Gc

Como o algoritmo escolhe s ∈ Ci para cada Ci ∈ P, e dentro de Ci todos os vértices se alcancam:

s ∈ Ci ∧ existe caminho de Ci até Cj ⇒ ∀ x ∈ Cj, existe caminho direcionado de s até x

Logo:

∀ x ∈ V, ∃ s ∈ S tal que existe caminho direcionado de s até x

Portanto:

V ⊆ F+(S)

Pela definição de F+(S):

∀ x, x ∈ F+(S) ⇒ x ∈ V

Assim:

F+(S) ⊆ V

Como:

V ⊆ F+(S) ∧ F+(S) ⊆ V

Concluimos:

F+(S) = V

Agora, mostramos que S é mínimo.

Se Ci é uma componente-fonte, então nenhuma outra componente chega até Ci:

Fonte(Ci) ⇒ ∀ Cj ∈ Vc, Cj ≠ Ci ⇒ não existe caminho direcionado de Cj até Ci

Logo, para algum vértice de Ci ser atingido, é necessário escolher pelo menos um vértice dentro de Ci:

Fonte(Ci) ⇒ ∀ S' ⊆ V, F+(S') = V ⇒ ∃ s ∈ S' tal que s ∈ Ci

Portanto, qualquer conjunto S' cujo fecho transitivo direto seja V precisa ter pelo menos um vértice de cada componente-fonte:

∀ S' ⊆ V, F+(S') = V ⇒ |S'| >= |P|

O algoritmo escolhé exatamente um vértice de cada componente-fonte:

|S| = |P|

Assim:

∀ S' ⊆ V, F+(S') = V ⇒ |S| <= |S'|

Conclusão:
O algoritmo retorna um conjunto S cujo fecho transitivo direto é V e cujo tamanho é mínimo. Esse conjunto é formado escolhendo exatamente um vértice de cada componente fortemente conexa que não possui aresta de entrada no grafo condensado.


Questão 13)

Enunciado:
Seja G = (V, E) um grafo direcionado. Projete uma solução para encontrar o menor conjunto de vértices cujo fecho transitivo direto seja V. Caso G seja cíclico, remova arestas para deixa-lo acíclico.

Ideia principal:
Primeiro verificamos se o grafo possui ciclos. Para remover ciclos, usamos DFS com estados: branco, cinza e preto. Quando encontramos uma aresta que aponta para um vértice cinza, essa aresta é uma aresta de retorno e fecha um ciclo. Então removemos essa aresta. Depois que todas as arestas de retorno forem removidas, o grafo fica acíclico. Em um grafo direcionado acíclico, o menor conjunto de vértices cujo fecho transitivo direto é V é formado por todos os vértices com grau de entrada zero.

Pseudocódigo:

Algoritmo MenorConjuntoAposRemoverCiclos(G)
Entrada: um grafo direcionado G = (V, E)
Saída: menor conjunto S tal que o fecho transitivo direto de S seja V no grafo acíclico resultante

início
    para cada vértice v pertencente a V faça
        cor[v] <- branco
    fim-para

    para cada vértice v pertencente a V faça
        se cor[v] = branco então
            DFS_RemoverCiclos(G, v)
        fim-se
    fim-para

    para cada vértice v pertencente a V faça
        entrada[v] <- 0
    fim-para

    para cada aresta (u, v) pertencente a E faça
        entrada[v] <- entrada[v] + 1
    fim-para

    S <- conjunto vazio

    para cada vértice v pertencente a V faça
        se entrada[v] = 0 então
            adicione v em S
        fim-se
    fim-para

    retorne S
fim

Procedimento DFS_RemoverCiclos(G, v)
início
    cor[v] <- cinza

    para cada aresta (v, w) pertencente a E faça
        se cor[w] = cinza então
            remova a aresta (v, w) de E
        senão se cor[w] = branco então
            DFS_RemoverCiclos(G, w)
        fim-se
    fim-para

    cor[v] <- preto
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Marque todos os vértices inicialmente como branco.
3. Execute uma DFS no grafo.
4. Quando um vértice começa a ser visitado, marque-o como cinza.
5. Quando a visita desse vértice termina, marque-o como preto.
6. Durante a DFS, se encontrar uma aresta (v, w) em que w está cinza, remova essa aresta.
7. Essa aresta é uma aresta de retorno, pois aponta para um vértice que ainda está na pilha da recursão.
8. Remover as arestas de retorno elimina os ciclos do grafo.
9. Depois disso, o grafo resultante e direcionado acíclico.
10. Calcule o grau de entrada de cada vértice no grafo resultante.
11. Escolha todos os vértices com grau de entrada zero.
12. Esses vértices formam o conjunto S.
13. Retorne S.

Prova matemática:

Seja G = (V, E) um grafo direcionado.

Durante a DFS, usamos:

cor[v] = cinza ⇔ v pertence a pilha atual da recursão

Se a DFS encontra uma aresta (u, v) tal que cor[v] = cinza, então v e ancestral de u na árvore DFS.

Logo:

cor[v] = cinza ∧ (u, v) ∈ E ⇒ existe caminho direcionado de v até u

Como também existe a aresta (u, v):

existe caminho de v até u ∧ (u, v) ∈ E ⇒ existe ciclo direcionado

Portanto, toda aresta removida pertence a algum ciclo:

∀ (u, v) ∈ E, cor[v] = cinza ⇒ (u, v) pertence a um ciclo

Chamemos de G' = (V, E') o grafo após a remocao das arestas de retorno.

Como em uma DFS de grafo direcionado éxiste ciclo se e somente se, existe aresta de retorno:

G possui ciclo ⇔ ∃ (u, v) ∈ E tal que v e ancestral de u na DFS

Como o algoritmo remove toda aresta de retorno:

∀ (u, v) ∈ E', v não e ancestral de u na DFS

Logo:

não existe aresta de retorno em E' ⇒ G' é acíclico

Agora, como G' é acíclico, todo vértice de G' é uma fonte ou e atingível a partir de alguma fonte.

Definimos o conjunto de fontes:

S = {v ∈ V | grauEntrada(v) = 0}

Para todo vértice x ∈ V:

x ∈ S ∨ grauEntrada(x) > 0

Se x ∉ S, então existe uma aresta éntrando em x:

x ∉ S ⇒ ∃ y ∈ V tal que (y, x) ∈ E'

Seguindo esse raciocinio para tras, como G' é acíclico, o processo não pode continuar infinitamente nem formar ciclo. Portanto, ele termina em algum vértice s com grau de entrada zero:

∀ x ∈ V, ∃ s ∈ S tal que existe caminho direcionado de s até x

Assim, o fecho transitivo direto de S em G' e:

F+(S) = {x ∈ V | ∃ s ∈ S tal que existe caminho direcionado de s até x}

Como todo x ∈ V e atingível a partir de algum s ∈ S:

∀ x ∈ V, x ∈ F+(S)

Logo:

V ⊆ F+(S)

Pela definição de fecho:

∀ x, x ∈ F+(S) ⇒ x ∈ V

Então:

F+(S) ⊆ V

Portanto:

V ⊆ F+(S) ∧ F+(S) ⊆ V ⇒ F+(S) = V

Agora, provamos que S é mínimo.

Se s ∈ S, então grauEntrada(s) = 0. Portanto, nenhum outro vértice chega em s por uma aresta de entrada direta. Em um grafo acíclico, se uma fonte fosse atingível a partir de outro vértice, existiria uma aresta de entrada em algum ponto antes dela, contradizendo que ela e fonte.

Assim:

∀ s ∈ S, ∀ x ∈ V, x ≠ s ⇒ não existe caminho direcionado de x até s

Logo, qualquer conjunto S' cujo fecho transitivo direto seja V precisa conter cada fonte:

∀ S' ⊆ V, F+(S') = V ⇒ S ⊆ S'

Portanto:

∀ S' ⊆ V, F+(S') = V ⇒ |S| <= |S'|

Conclusão:
O algoritmo remove as arestas de retorno encontradas pela DFS, deixando o grafo acíclico. Depois escolhe todos os vértices com grau de entrada zero. Esse conjunto possui fecho transitivo direto igual a V e é mínimo no grafo acíclico resultante.


Questão 14)

Enunciado:
Seja G = (V, E) um grafo não-direcionado. Projete uma solução para encontrar, dado v pertencente a V, o vértice mais distante de v.

Ideia principal:
Como o grafo não possui pesos nas arestas, a distância entre dois vértices é a menor quantidade de arestas em um caminho entre eles. Para encontrar o vértice mais distante de v, usamos BFS a partir de v. A BFS calcula a menor distância de v até todos os vértices alcançáveis. Depois, basta escolher o vértice que possui a maior distância calculada. Se o grafo não for conexo, consideramos apenas os vértices alcançáveis a partir de v.

Pseudocódigo:

Algoritmo VerticeMaisDistante(G, v)
Entrada: um grafo não-direcionado G = (V, E) e um vértice v pertencente a V
Saída: um vértice mais distante de v entre os vértices alcançáveis

início
    para cada vértice x pertencente a V faça
        visitado[x] <- falso
        distância[x] <- infinito
    fim-para

    visitado[v] <- verdadeiro
    distância[v] <- 0

    fila <- fila vazia
    enfileire v em fila

    enquanto fila não estiver vazia faça
        atual <- desenfileire fila

        para cada vértice w adjacente a atual faça
            se visitado[w] = falso então
                visitado[w] <- verdadeiro
                distância[w] <- distância[atual] + 1
                enfileire w em fila
            fim-se
        fim-para
    fim-enquanto

    maisDistante <- v

    para cada vértice x pertencente a V faça
        se visitado[x] = verdadeiro e distância[x] > distância[maisDistante] então
            maisDistante <- x
        fim-se
    fim-para

    retorne maisDistante
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo não-direcionado.
2. Escolha o vértice inicial v pertencente a V.
3. Marque todos os vértices como não visitados.
4. Defina a distância de todos os vértices como infinito.
5. Coloque distância[v] = 0 e marque v como visitado.
6. Insira v em uma fila.
7. Enquanto a fila não estiver vazia, remova o primeiro vértice da fila.
8. Para cada vizinho ainda não visitado, marque-o como visitado.
9. A distância desse vizinho será a distância do vértice atual mais 1.
10. Coloque o vizinho na fila.
11. Ao final da BFS, todos os vértices alcançáveis a partir de v teráo suas menores distâncias calculadas.
12. Percorra todos os vértices visitados.
13. Escolha o vértice que possui a maior distância em relação a v.
14. Retorne esse vértice como o mais distante.

Prova matemática:

Seja G = (V, E) um grafo não-direcionado é seja v ∈ V.

Definimos a distância mínima entre v e x como:

δ(v, x) = menor número de arestas em um caminho de v até x

Se x não for alcançável a partir de v:

δ(v, x) = infinito

A BFS inicia com:

distância[v] = 0

Como existe caminho de tamanho 0 de v até v:

distância[v] = δ(v, v) = 0

Durante a BFS, se um vértice w é descoberto a partir de atual, então existe uma aresta entre atual e w:

{atual, w} ∈ E

e:

distância[w] = distância[atual] + 1

Logo:

∀ atual, w ∈ V, {atual, w} ∈ E ∧ distância[atual] = k ⇒ distância[w] = k + 1

Como a BFS usa fila, todos os vértices a distância k são processados antes dos vértices a distância k + 1:

∀ a, b ∈ V, distância[a] < distância[b] ⇒ a e processado antes de b

Assim, a primeira vez que um vértice x é visitado, ele foi encontrado pelo menor caminho possível:

∀ x ∈ V, visitado[x] = verdadeiro ⇒ distância[x] = δ(v, x)

O algoritmo escolhe maisDistante tal que:

∀ x ∈ V, visitado[x] = verdadeiro ⇒ distância[x] <= distância[maisDistante]

Como:

distância[x] = δ(v, x)

temos:

∀ x ∈ V, visitado[x] = verdadeiro ⇒ δ(v, x) <= δ(v, maisDistante)

Portanto, maisDistante possui a maior distância em relação a v entre todos os vértices alcançáveis.

Se o grafo for conexo:

∀ x ∈ V, visitado[x] = verdadeiro

Logo:

∀ x ∈ V, δ(v, x) <= δ(v, maisDistante)

Conclusão:
O algoritmo encontra corretamente o vértice mais distante de v, pois a BFS calcula a menor distância de v até cada vértice alcançável, e depois o algoritmo escolhe aquele cuja distância é máxima.


Questão 15)

Enunciado:
Existe algum tipo de grafo em que o centro terá sempre um vértice? No máximo 2 vértices no centro?

Ideia principal:
Sim. Em uma árvore, o centro sempre possui exatamente 1 ou 2 vértices. O centro de um grafo é o conjunto dos vértices com menor excentricidade. A excentricidade de um vértice v é a maior distância de v até qualquer outro vértice do grafo. Em uma árvore, podemos encontrar o centro removendo repetidamente todas as folhas. Quando esse processo termina, sobra exatamente 1 vértice ou 2 vértices. Esse conjunto restante é o centro da árvore.

Pseudocódigo:

Algoritmo CentroDaArvore(T)
Entrada: uma árvore T = (V, E)
Saída: centro da árvore, contendo 1 ou 2 vértices

início
    se |V| <= 2 então
        retorne V
    fim-se

    para cada vértice v pertencente a V faça
        grau[v] <- quantidade de vizinhos de v
    fim-para

    folhas <- conjunto vazio

    para cada vértice v pertencente a V faça
        se grau[v] = 1 então
            adicione v em folhas
        fim-se
    fim-para

    restantes <- |V|

    enquanto restantes > 2 faça
        novasFolhas <- conjunto vazio
        restantes <- restantes - |folhas|

        para cada vértice f pertencente a folhas faça
            para cada vértice u adjacente a f faça
                grau[u] <- grau[u] - 1

                se grau[u] = 1 então
                    adicione u em novasFolhas
                fim-se
            fim-para
        fim-para

        folhas <- novasFolhas
    fim-enquanto

    retorne folhas
fim

Passo a passo para resolver:

1. Considere T = (V, E) uma árvore.
2. O centro de T é formado pelos vértices que possuem menor excentricidade.
3. A excentricidade de um vértice v é a maior distância de v até qualquer outro vértice da árvore.
4. Em uma árvore, os vértices mais externos são as folhas.
5. Remova todas as folhas ao mesmo tempo.
6. Depois da remocao, novos vértices podem se tornar folhas.
7. Repita o processo de remover folhas camada por camada.
8. Quando sobrarem 1 ou 2 vértices, pare.
9. Os vértices restantes formam o centro da árvore.
10. Portanto, em árvores, o centro sempre possui 1 ou 2 vértices.

Prova matemática:

Seja T = (V, E) uma árvore.

Definimos a distância entre dois vértices u e v como:

d(u, v) = número de arestas no único caminho entre u e v

A excentricidade de um vértice v e:

ecc(v) = max {d(v, x) | x ∈ V}

O centro da árvore e:

C(T) = {v ∈ V | ∀ u ∈ V, ecc(v) <= ecc(u)}

Queremos mostrar que:

|C(T)| = 1 ∨ |C(T)| = 2

Em uma árvore, entre quaisquer dois vértices existe um único caminho:

∀ u, v ∈ V, ∃! caminho simples entre u e v

Considere um caminho mais longo da árvore, chamado diâmetro:

P = v0, v1, v2, ..., vk

tal que:

∀ x, y ∈ V, d(x, y) <= k

e:

d(v0, vk) = k

O centro da árvore está no meio desse caminho mais longo.

Se k é par, existe um único vértice central:

k = 2m ⇒ centro = {vm}

Nesse caso:

∀ x ∈ V, ecc(vm) <= ecc(x)

Logo:

C(T) = {vm}

Portanto:

k = 2m ⇒ |C(T)| = 1

Se k é ímpar, existem dois vértices centrais:

k = 2m + 1 ⇒ centro = {vm, vm+1}

Nesse caso:

∀ x ∈ V, ecc(vm) <= ecc(x) ∧ ecc(vm+1) <= ecc(x)

Logo:

C(T) = {vm, vm+1}

Portanto:

k = 2m + 1 ⇒ |C(T)| = 2

Agora relacionamos isso com o algoritmo de remover folhas.

As folhas estão nas extremidades dos caminhos mais longos da árvore:

∀ f ∈ V, grau(f) = 1 ⇒ f pode estar em uma camada externa da árvore

Ao remover todas as folhas, diminuimos igualmente as extremidades dos caminhos mais longos:

∀ camada removida, o comprimento do diâmetro diminui em 2

Assim, o processo preserva o meio do diâmetro:

∀ i >= 0, remover a i-esima camada de folhas ⇒ o centro permanece o mesmo

Quando o processo termina, restam apenas os vértices centrais:

restantes <= 2 ⇒ restantes = C(T)

Portanto:

T é árvore ⇒ |C(T)| <= 2

Como toda árvore não vazia possui pelo menos um vértice:

|V| >= 1 ⇒ |C(T)| >= 1

Logo:

T é árvore ∧ |V| >= 1 ⇒ 1 <= |C(T)| <= 2

Conclusão:
Sim. As árvores são um tipo de grafo em que o centro sempre possui pelo menos 1 vértice e no máximo 2 vértices. O algoritmo de remover folhas encontra esse centro corretamente, pois remove as camadas externas da árvore até restar exatamente o meio do diâmetro.


Questão 16)

Enunciado:
Dado um grafo não-direcionado é conexo, prove que:

raio(G) <= diâmetro(G) <= 2 · raio(G)

Ideia principal:
Em um grafo conexo, a excentricidade de um vértice v é a maior distância de v até qualquer outro vértice. O raio do grafo é a menor excentricidade entre todos os vértices. O diâmetro é a maior distância entre dois vértices quaisquer, ou seja, a maior excentricidade. Como o raio é o menor valor e o diâmetro é o maior valor, temos raio(G) <= diâmetro(G). Além disso, se c é um vértice central, então todo vértice está a distância no máximo raio(G) de c. Assim, quaisquer dois vértices u e v estão a distância no máximo raio(G) + raio(G), logo diâmetro(G) <= 2 · raio(G).

Pseudocódigo:

Algoritmo VerificarRaioDiametro(G)
Entrada: um grafo não-direcionado conexo G = (V, E)
Saída: raio(G), diâmetro(G) e verificacao da desigualdade

início
    para cada vértice v pertencente a V faça
        distância <- BFS(G, v)
        excentricidade[v] <- maior distância de v até qualquer vértice de V
    fim-para

    raio <- infinito
    diâmetro <- 0

    para cada vértice v pertencente a V faça
        se excentricidade[v] < raio então
            raio <- excentricidade[v]
        fim-se

        se excentricidade[v] > diâmetro então
            diâmetro <- excentricidade[v]
        fim-se
    fim-para

    se raio <= diâmetro e diâmetro <= 2 * raio então
        retorne raio, diâmetro, verdadeiro
    senão
        retorne raio, diâmetro, falso
    fim-se
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo não-direcionado é conexo.
2. Para cada vértice v pertencente a V, calcule a distância de v até todos os outros vértices usando BFS.
3. Para cada v, encontre sua excentricidade, isto é, a maior distância de v até algum vértice do grafo.
4. O raio de G é a menor excentricidade entre todos os vértices.
5. O diâmetro de G é a maior excentricidade entre todos os vértices.
6. Como o raio é o menor valor das excentricidades e o diâmetro é o maior valor, então raio(G) <= diâmetro(G).
7. Escolha um vértice central c, isto é, um vértice cuja excentricidade é igual ao raio.
8. Para quaisquer vértices u e v, a distância de u até v e no máximo a distância de u até c mais a distância de c até v.
9. Como c e central, d(c, u) <= raio(G) e d(c, v) <= raio(G).
10. Logo, d(u, v) <= 2 · raio(G).
11. Como o diâmetro é a maior distância entre dois vértices quaisquer, concluímos que diâmetro(G) <= 2 · raio(G).

Prova matemática:

Seja G = (V, E) um grafo não-direcionado conexo.

Definimos a distância entre dois vértices u e v como:

d(u, v) = menor número de arestas em um caminho entre u e v

Como G é conexo:

∀ u, v ∈ V, existe caminho entre u e v

Logo:

∀ u, v ∈ V, d(u, v) ∈ N

A excentricidade de um vértice v e:

ecc(v) = max {d(v, x) | x ∈ V}

O raio de G é:

raio(G) = min {ecc(v) | v ∈ V}

O diâmetro de G é:

diâmetro(G) = max {ecc(v) | v ∈ V}

Como o mínimo de um conjunto é menor ou igual ao máximo do mesmo conjunto:

min {ecc(v) | v ∈ V} <= max {ecc(v) | v ∈ V}

Portanto:

raio(G) <= diâmetro(G)

Agora, seja c ∈ V um vértice central, isto é:

ecc(c) = raio(G)

Pela definição de excentricidade:

∀ x ∈ V, d(c, x) <= ecc(c)

Como ecc(c) = raio(G):

∀ x ∈ V, d(c, x) <= raio(G)

Para quaisquer u, v ∈ V, pela desigualdade triangular:

d(u, v) <= d(u, c) + d(c, v)

Como o grafo é não-direcionado:

d(u, c) = d(c, u)

E como:

d(c, u) <= raio(G) ∧ d(c, v) <= raio(G)

temos:

d(u, v) <= raio(G) + raio(G)

Logo:

∀ u, v ∈ V, d(u, v) <= 2 · raio(G)

Como o diâmetro é a maior distância entre dois vértices:

diâmetro(G) = max {d(u, v) | u, v ∈ V}

Então:

∀ u, v ∈ V, d(u, v) <= 2 · raio(G) ⇒ diâmetro(G) <= 2 · raio(G)

Juntando os dois resultados:

raio(G) <= diâmetro(G) ∧ diâmetro(G) <= 2 · raio(G)

Portanto:

raio(G) <= diâmetro(G) <= 2 · raio(G)

Conclusão:
Em todo grafo não-direcionado conexo, o raio é sempre menor ou igual ao diâmetro, e o diâmetro é sempre menor ou igual ao dobro do raio.


Questão 17)

Enunciado:
Seja G um grafo direcionado. Como seria o conceito de centro em G? Adapte da definição de grafo não-direcionado.

Ideia principal:
Em um grafo não-direcionado, o centro é formado pelos vértices que possuem menor excentricidade, isto é, pelos vértices cuja maior distância até os outros vértices é a menor possível. Em um grafo direcionado, a diferença é que a distância deve respeitar o sentido das arestas. Assim, a distância de u até v pode ser diferente da distância de v até u. O centro direcionado pode ser definido como o conjunto dos vértices com menor excentricidade de saída, ou seja, aqueles que conseguem atingir todos os outros vértices com a menor maior distância possível. Se algum vértice não puder ser atingido a partir de u, então a excentricidade de u é infinita.

Pseudocódigo:

Algoritmo CentroGrafoDirecionado(G)
Entrada: um grafo direcionado G = (V, E)
Saída: conjunto C com os vértices centrais de G

início
    para cada vértice v pertencente a V faça
        distância <- BFS_Direcionada(G, v)

        se existe x pertencente a V tal que distância[x] = infinito então
            excentricidade[v] <- infinito
        senão
            excentricidade[v] <- maior distância de v até qualquer x pertencente a V
        fim-se
    fim-para

    raio <- menor valor de excentricidade[v], para todo v pertencente a V

    C <- conjunto vazio

    para cada vértice v pertencente a V faça
        se excentricidade[v] = raio então
            adicione v em C
        fim-se
    fim-para

    retorne C
fim

Procedimento BFS_Direcionada(G, origem)
início
    para cada vértice x pertencente a V faça
        distância[x] <- infinito
        visitado[x] <- falso
    fim-para

    distância[origem] <- 0
    visitado[origem] <- verdadeiro
    fila <- fila vazia
    enfileire origem em fila

    enquanto fila não estiver vazia faça
        u <- desenfileire fila

        para cada aresta (u, w) pertencente a E faça
            se visitado[w] = falso então
                visitado[w] <- verdadeiro
                distância[w] <- distância[u] + 1
                enfileire w em fila
            fim-se
        fim-para
    fim-enquanto

    retorne distância
fim

Passo a passo para resolver:

1. Considere G = (V, E) um grafo direcionado.
2. Para adaptar o conceito de centro, use distâncias direcionadas.
3. A distância d(u, v) é o menor caminho direcionado de u até v.
4. Se não existir caminho direcionado de u até v, então d(u, v) = infinito.
5. Para cada vértice v, execute uma BFS direcionada a partir de v.
6. Essa BFS deve seguir apenas as arestas que saem do vértice atual.
7. Calcule a excentricidade de v como a maior distância de v até qualquer outro vértice.
8. Se algum vértice não for alcançável a partir de v, a excentricidade de v será infinita.
9. Depois de calcular todas as excentricidades, encontre o menor valor entre elas.
10. Esse menor valor é o raio direcionado do grafo.
11. O centro direcionado é o conjunto de todos os vértices cuja excentricidade é igual ao raio direcionado.

Prova matemática:

Seja G = (V, E) um grafo direcionado.

Definimos a distância direcionada de u até v como:

d+(u, v) = menor número de arestas em um caminho direcionado de u até v

Se não existir caminho direcionado de u até v:

d+(u, v) = infinito

Assim:

∀ u, v ∈ V, d+(u, v) ∈ N ∪ {infinito}

A excentricidade de saída de um vértice u e:

ecc+(u) = max {d+(u, x) | x ∈ V}

O raio direcionado de G é:

raio+(G) = min {ecc+(u) | u ∈ V}

O centro direcionado de G é:

C+(G) = {u ∈ V | ecc+(u) = raio+(G)}

O algoritmo calcula BFS_Direcionada(G, u) para todo u ∈ V.

Pela corretude da BFS em grafo não ponderado:

∀ u, x ∈ V, BFS_Direcionada(G, u) calcula distância[x] = d+(u, x)

Como a BFS direcionada segue somente arestas de saída:

∀ a, b ∈ V, b é visitado a partir de a ⇒ (a, b) ∈ E

Logo, toda distância calculada respeita o sentido das arestas:

∀ u, x ∈ V, distância[x] = k ⇒ existe caminho direcionado de u até x com k arestas

Se x não e alcançável a partir de u:

não existe caminho direcionado de u até x ⇒ distância[x] = infinito

Portanto, para cada u ∈ V, o algoritmo calcula:

excentricidade[u] = max {distância[x] | x ∈ V}

Como distância[x] = d+(u, x), temos:

∀ u ∈ V, excentricidade[u] = max {d+(u, x) | x ∈ V}

Logo:

∀ u ∈ V, excentricidade[u] = ecc+(u)

Depois, o algoritmo escolhe:

raio = min {excentricidade[u] | u ∈ V}

Como excentricidade[u] = ecc+(u):

raio = min {ecc+(u) | u ∈ V}

Logo:

raio = raio+(G)

Por fim, o algoritmo retorna:

C = {u ∈ V | excentricidade[u] = raio}

Substituindo pelas definições:

C = {u ∈ V | ecc+(u) = raio+(G)}

Portanto:

C = C+(G)

Conclusão:
Em grafos direcionados, o centro pode ser definido como o conjunto dos vértices com menor excentricidade de saída. O algoritmo calcula corretamente esse centro, pois usa BFS direcionada para obter as distâncias respeitando o sentido das arestas e escolhé exatamente os vértices cuja excentricidade é mínima.


Questão 18)

Enunciado:
Seja G = (V, E) um grafo direcionado. Projete um algoritmo para identificar se G é fortemente conexo.

Ideia principal:
Um grafo direcionado é fortemente conexo quando todo vértice consegue alcançar todos os outros vértices respeitando o sentido das arestas. Uma forma eficiente de testar isso e fazer uma busca em profundidade a partir de um vértice qualquer no grafo original e depois fazer outra busca a partir do mesmo vértice no grafo transposto, isto é, no grafo com todas as arestas invertidas. Se as duas buscas visitarem todos os vértices, então o grafo é fortemente conexo.

Pseudocódigo:

Algoritmo EhFortementeConexo(G)
Entrada: um grafo direcionado G = (V, E)
Saída: verdadeiro se G for fortemente conexo; falso caso contrário

início
    escolha um vértice s pertencente a V

    visitado <- DFS(G, s)

    se existe v pertencente a V tal que visitado[v] = falso então
        retorne falso
    fim-se

    GT <- grafo transposto de G

    visitadoT <- DFS(GT, s)

    se existe v pertencente a V tal que visitadoT[v] = falso então
        retorne falso
    fim-se

    retorne verdadeiro
fim

Procedimento GrafoTransposto(G)
início
    crie GT com o mesmo conjunto de vértices de G

    para cada aresta (u, v) pertencente a E faça
        adicione a aresta (v, u) em GT
    fim-para

    retorne GT
fim

Passo a passo para resolver:

1. Escolha um vértice inicial s.
2. Execute uma DFS em G a partir de s.
3. Se algum vértice não foi visitado, então s não alcanca todos os vértices, logo G não é fortemente conexo.
4. Construa o grafo transposto GT, invertendo o sentido de todas as arestas.
5. Execute uma DFS em GT a partir de s.
6. Se algum vértice não foi visitado em GT, então no grafo original esse vértice não consegue chegar até s.
7. Se as duas buscas visitarem todos os vértices, então s alcanca todos e todos alcancam s.
8. Logo, todos os vértices alcancam todos os outros, e G é fortemente conexo.

Prova matemática:

Seja G = (V, E) um grafo direcionado é seja s pertencente a V.

Um grafo é fortemente conexo se:

para todo u, v pertencentes a V, existe caminho direcionado de u até v

Na primeira DFS:

para todo v pertencente a V, visitado[v] = verdadeiro

Isso significa:

para todo v pertencente a V, existe caminho direcionado de s até v em G

Na segunda DFS, feita no grafo transposto GT:

para todo v pertencente a V, visitadoT[v] = verdadeiro

Isso significa que, em GT, existe caminho de s até v.
Como GT tem todas as arestas invertidas, isso equivale a dizer que, em G, existe caminho de v até s.

Logo:

para todo v pertencente a V, existe caminho de s até v
e
para todo v pertencente a V, existe caminho de v até s

Agora, para quaisquer u, v pertencentes a V:

u consegue chegar até s
e
s consegue chegar até v

Portanto, juntando os caminhos:

u -> s -> v

Assim, existe caminho de u até v.
Como u e v eram quaisquer, G é fortemente conexo.

Conclusão:
O algoritmo identifica corretamente se G é fortemente conexo, pois verifica se um vértice s alcanca todos os outros e se todos os outros conseguem alcançar s.


Questão 19)

Enunciado:
Achar todos os componentes fortemente conexos, pensando usando conceito de busca em profundidade.

Ideia principal:
Uma componente fortemente conexa é um maior conjunto de vértices em que todos conseguem alcançar todos os outros por caminhos direcionados. Podemos encontrar todas as componentes usando o algoritmo de Kosaraju. Ele faz uma DFS no grafo original para calcular os tempos de termino, depois cria o grafo transposto e faz DFS nele seguindo a ordem decrescente dos tempos de termino. Cada DFS no grafo transposto encontra uma componente fortemente conexa.

Pseudocódigo:

Algoritmo ComponentesFortementeConexas(G)
Entrada: um grafo direcionado G = (V, E)
Saída: lista das componentes fortemente conexas de G

início
    para cada vértice v pertencente a V faça
        visitado[v] <- falso
    fim-para

    pilha <- pilha vazia

    para cada vértice v pertencente a V faça
        se visitado[v] = falso então
            DFS_TempoTermino(G, v, visitado, pilha)
        fim-se
    fim-para

    GT <- grafo transposto de G

    para cada vértice v pertencente a V faça
        visitado[v] <- falso
    fim-para

    componentes <- lista vazia

    enquanto pilha não estiver vazia faça
        v <- desempilhe(pilha)

        se visitado[v] = falso então
            componente <- conjunto vazio
            DFS_Coleta(GT, v, visitado, componente)
            adicione componente em componentes
        fim-se
    fim-enquanto

    retorne componentes
fim

Procedimento DFS_TempoTermino(G, v, visitado, pilha)
início
    visitado[v] <- verdadeiro

    para cada vértice w sucessor de v faça
        se visitado[w] = falso então
            DFS_TempoTermino(G, w, visitado, pilha)
        fim-se
    fim-para

    empilhe v em pilha
fim

Procedimento DFS_Coleta(GT, v, visitado, componente)
início
    visitado[v] <- verdadeiro
    adicione v em componente

    para cada vértice w sucessor de v em GT faça
        se visitado[w] = falso então
            DFS_Coleta(GT, w, visitado, componente)
        fim-se
    fim-para
fim

Passo a passo para resolver:

1. Execute DFS no grafo original.
2. Quando um vértice terminar sua visita, coloque esse vértice em uma pilha.
3. Inverta todas as arestas do grafo, formando o grafo transposto GT.
4. Reinicie todos os vértices como não visitados.
5. Retire vértices da pilha, isto é, siga a ordem decrescente de tempo de termino.
6. Para cada vértice ainda não visitado, execute DFS no grafo transposto.
7. Todos os vértices visitados nessa DFS formam uma componente fortemente conexa.
8. Repita até a pilha ficar vazia.

Justificativa:
Os tempos de termino da primeira DFS ajudam a escolher um vértice que representa uma componente "mais externa" no grafo de componentes. Ao inverter as arestas e buscar nessa ordem, a DFS fica presa exatamente dentro de uma componente fortemente conexa, sem misturar componentes diferentes.

Conclusão:
O algoritmo de Kosaraju encontra todas as componentes fortemente conexas usando duas buscas em profundidade e o grafo transposto.


Questão 20)

Enunciado:
Seja G = (V, E) um grafo direcionado. Apresente, pelo menos, duas estratégias diferentes para determinar se G é cíclico.

Ideia principal:
Um grafo direcionado é cíclico quando existe um caminho direcionado que sai de um vértice é volta para ele. Duas estratégias comuns para detectar ciclos são: DFS com pilha de recursão e ordenação topológica pelo algoritmo de Kahn.

Estrategia 1: DFS com pilha de recursão

Pseudocódigo:

Algoritmo TemCicloDFS(G)
Entrada: um grafo direcionado G = (V, E)
Saída: verdadeiro se G possuir ciclo

início
    para cada vértice v pertencente a V faça
        cor[v] <- branco
    fim-para

    para cada vértice v pertencente a V faça
        se cor[v] = branco então
            se DFS_Ciclo(G, v, cor) = verdadeiro então
                retorne verdadeiro
            fim-se
        fim-se
    fim-para

    retorne falso
fim

Procedimento DFS_Ciclo(G, v, cor)
início
    cor[v] <- cinza

    para cada sucessor w de v faça
        se cor[w] = cinza então
            retorne verdadeiro
        fim-se

        se cor[w] = branco então
            se DFS_Ciclo(G, w, cor) = verdadeiro então
                retorne verdadeiro
            fim-se
        fim-se
    fim-para

    cor[v] <- preto
    retorne falso
fim

Explicação:
Branco significa não visitado.
Cinza significa que o vértice está sendo visitado, ou seja, está na pilha da DFS.
Preto significa que a visita terminou.
Se encontramos uma aresta para um vértice cinza, encontramos uma aresta de retorno, logo existe ciclo.

Estrategia 2: Ordenação topológica por Kahn

Pseudocódigo:

Algoritmo TemCicloKahn(G)
Entrada: um grafo direcionado G = (V, E)
Saída: verdadeiro se G possuir ciclo

início
    para cada vértice v pertencente a V faça
        grauEntrada[v] <- quantidade de arestas que chegam em v
    fim-para

    fila <- vértices com grauEntrada igual a 0
    removidos <- 0

    enquanto fila não estiver vazia faça
        v <- desenfileire fila
        removidos <- removidos + 1

        para cada sucessor w de v faça
            grauEntrada[w] <- grauEntrada[w] - 1

            se grauEntrada[w] = 0 então
                enfileire w em fila
            fim-se
        fim-para
    fim-enquanto

    se removidos < |V| então
        retorne verdadeiro
    senão
        retorne falso
    fim-se
fim

Explicação:
Todo DAG possui pelo menos uma fonte, isto é, um vértice com grau de entrada zero.
O algoritmo remove fontes repetidamente.
Se ao final nem todos os vértices foram removidos, os vértices restantes fazem parte de algum ciclo ou dependem de um ciclo.

Conclusão:
As duas estratégias funcionam para grafos direcionados. Pela DFS, ciclo aparece como aresta de retorno. Pela ordenação topológica, ciclo aparece quando não conseguimos remover todos os vértices.


Questão 21)

Enunciado:
Seja G = (V, E) um grafo direcionado acíclico. Apresente, pelo menos, duas estratégias para encontrar o maior caminho de G.

Ideia principal:
Como G é direcionado é acíclico, ele é um DAG. Em DAGs, o maior caminho pode ser encontrado sem cair em repeticoes infinitas, pois não existem ciclos. Duas estratégias são: programação dinâmica em ordem topológica e DFS com memoização.

Estrategia 1: Programacao dinâmica usando ordenação topológica

Pseudocódigo:

Algoritmo MaiorCaminhoDAG_Topologico(G)
Entrada: um DAG G = (V, E)
Saída: tamanho do maior caminho de G em número de arestas

início
    ordem <- OrdenaçãoTopologica(G)

    para cada vértice v pertencente a V faça
        dist[v] <- 0
    fim-para

    para cada vértice u em ordem faça
        para cada sucessor v de u faça
            se dist[v] < dist[u] + 1 então
                dist[v] <- dist[u] + 1
            fim-se
        fim-para
    fim-para

    retorne maior valor de dist[v], para v pertencente a V
fim

Explicação:
dist[v] guarda o tamanho do maior caminho que termina em v.
Ao processar os vértices em ordem topológica, todo predecessor de v já foi considerado antes de v.
Para cada aresta (u, v), podemos estender um caminho que termina em u e obter um caminho que termina em v.

Estrategia 2: DFS com memoização

Pseudocódigo:

Algoritmo MaiorCaminhoDAG_DFS(G)
Entrada: um DAG G = (V, E)
Saída: tamanho do maior caminho de G em número de arestas

início
    para cada vértice v pertencente a V faça
        memo[v] <- indefinido
    fim-para

    resposta <- 0

    para cada vértice v pertencente a V faça
        resposta <- max(resposta, MaiorAPartirDe(v))
    fim-para

    retorne resposta
fim

Função MaiorAPartirDe(v)
início
    se memo[v] está definido então
        retorne memo[v]
    fim-se

    melhor <- 0

    para cada sucessor w de v faça
        melhor <- max(melhor, 1 + MaiorAPartirDe(w))
    fim-para

    memo[v] <- melhor
    retorne melhor
fim

Explicação:
MaiorAPartirDe(v) calcula o tamanho do maior caminho que começa em v.
Como o grafo não tem ciclos, a recursão sempre termina.
A memoização evita recalcular a resposta para o mesmo vértice várias vezes.

Conclusão:
Em DAGs, o maior caminho pode ser resolvido de forma eficiente porque a ausencia de ciclos permite ordenar dependencias e reaproveitar resultados.


Questão 22)

Enunciado:
Qual a caracteristica importante que há em grafo acíclico?

Ideia principal:
A caracteristica mais importante de um grafo direcionado acíclico e que ele não possui ciclos e, por isso, admite ordenação topológica. Isso permite organizar os vértices em uma ordem de dependencia: se existe uma aresta (u, v), então u deve aparecer antes de v.

Resposta:
Em um grafo direcionado acíclico, chamado DAG, é possível fazer uma ordenação topológica dos vértices.

Isso significa que podemos numerar ou ordenar os vértices de modo que toda aresta respeite a ordem:

se (u, v) pertence a E, então u aparece antes de v

Explicação:
Essa propriedade e muito importante porque permite modelar problemas de dependencia.
Por exemplo:
- tarefas de uma obra;
- disciplinas com pre-requisitos;
- etapas de compilacao;
- processos que precisam acontecer em ordem.

Outra caracteristica importante e que todo DAG finito não vazio possui pelo menos uma fonte e pelo menos um sorvedouro.
Fonte é um vértice com grau de entrada zero.
Sorvedouro é um vértice com grau de saída zero.

Justificativa:
Se um grafo direcionado finito não tivesse fonte, todo vértice teria pelo menos uma aresta chegando.
Então poderíamos voltar por predecessores indefinidamente.
Como o grafo é finito, em algum momento um vértice repetiria, formando um ciclo.
Isso contradiz o fato de o grafo ser acíclico.
Logo, deve existir pelo menos uma fonte.

Conclusão:
A caracteristica essencial de um DAG e permitir uma ordem topológica, o que torna possível resolver problemas de dependencias, detectar ciclos e calcular maior caminho de forma organizada.


Questão 23)

Enunciado:
Seja G = (V, E) um grafo direcionado. Identifique uma base de V, com a menor quantidadé possível de vértices.

Ideia principal:
Uma base é um conjunto S de vértices tal que o fecho transitivo direto de S cobre todos os vértices do grafo. Em outras palavras, a partir dos vértices de S conseguimos atingir todos os vértices de V. Para um grafo direcionado geral, uma forma correta e contrair as componentes fortemente conexas, formando o grafo condensado. Esse grafo condensado sempre é acíclico. Então escolhemos uma componente fonte, isto é, com grau de entrada zero, e pegamos um vértice representante de cada uma dessas componentes. Esses representantes formam uma base mínima.

Pseudocódigo:

Algoritmo BaseMinimaGrafoDirecionado(G)
Entrada: um grafo direcionado G = (V, E)
Saída: uma base mínima S

início
    componentes <- ComponentesFortementeConexas(G)

    construa o grafo condensado GC
    cada componente fortemente conexa vira um vértice ém GC

    para cada aresta (u, v) pertencente a E faça
        Cu <- componente que contém u
        Cv <- componente que contém v

        se Cu diferente de Cv então
            adicione a aresta (Cu, Cv) em GC
        fim-se
    fim-para

    S <- conjunto vazio

    para cada componente C em GC faça
        se grauEntrada(C) = 0 então
            escolha um vértice x pertencente a C
            adicione x em S
        fim-se
    fim-para

    retorne S
fim

Passo a passo para resolver:

1. Encontre as componentes fortemente conexas do grafo.
2. Contraia cada componente em um único vértice.
3. O grafo resultante é chamado grafo condensado.
4. O grafo condensado e sempre um DAG.
5. Encontre as fontes do grafo condensado.
6. Para cada componente fonte, escolha um vértice representante.
7. O conjunto desses representantes é uma base mínima.

Justificativa:
Dentro de uma componente fortemente conexa, qualquer vértice alcanca todos os outros da mesma componente.
No grafo condensado, uma componente fonte não pode ser alcançada por nenhuma outra componente, pois ela não tem entrada.
Portanto, qualquer base precisa escolher pelo menos um vértice de cada componente fonte.
Escolhendo exatamente um vértice de cada componente fonte, conseguimos alcançar todas as componentes do grafo condensado e, consequentemente, todos os vértices de G.

Conclusão:
A base mínima de um grafo direcionado geral pode ser obtida escolhendo um representante de cada componente fonte do grafo condensado.


Questão 24)

Enunciado:
Seja G = (V, E) um grafo direcionado acíclico. Faça:
1) Encontre o maior caminho do grafo usando, pelo menos, duas estratégias diferentes.
2) De números para os vértices entre [1, |V|] de forma que a numeração respeite as arestas do grafo.

Ideia principal:
Como G é acíclico e direcionado, G é um DAG. Em um DAG podemos fazer ordenação topológica. Essa ordenação permite numerar os vértices e também calcular o maior caminho. Para o maior caminho, podemos usar programação dinâmica em ordem topológica ou DFS com memoização.

Parte 1: maior caminho usando duas estratégias

Estrategia A: programação dinâmica em ordem topológica

Pseudocódigo:

Algoritmo MaiorCaminhoTopologico(G)
Entrada: um DAG G = (V, E)
Saída: maior caminho em número de arestas

início
    ordem <- OrdenaçãoTopologica(G)

    para cada v pertencente a V faça
        dist[v] <- 0
        anterior[v] <- nulo
    fim-para

    para cada u em ordem faça
        para cada aresta (u, v) pertencente a E faça
            se dist[v] < dist[u] + 1 então
                dist[v] <- dist[u] + 1
                anterior[v] <- u
            fim-se
        fim-para
    fim-para

    fimCaminho <- vértice com maior dist[v]
    reconstrua o caminho voltando por anterior

    retorne caminho e dist[fimCaminho]
fim

Estrategia B: DFS com memoização

Pseudocódigo:

Algoritmo MaiorCaminhoMemoizacao(G)
Entrada: um DAG G = (V, E)
Saída: maior caminho em número de arestas

início
    para cada v pertencente a V faça
        memo[v] <- indefinido
        proximo[v] <- nulo
    fim-para

    melhorInicio <- nulo
    melhorValor <- 0

    para cada v pertencente a V faça
        valor <- MaiorAPartirDe(v)

        se valor > melhorValor então
            melhorValor <- valor
            melhorInicio <- v
        fim-se
    fim-para

    reconstrua o caminho a partir de melhorInicio usando proximo

    retorne caminho e melhorValor
fim

Função MaiorAPartirDe(v)
início
    se memo[v] está definido então
        retorne memo[v]
    fim-se

    memo[v] <- 0

    para cada sucessor w de v faça
        valor <- 1 + MaiorAPartirDe(w)

        se valor > memo[v] então
            memo[v] <- valor
            proximo[v] <- w
        fim-se
    fim-para

    retorne memo[v]
fim

Explicação:
As duas estratégias funcionam porque o grafo não tem ciclos.
Na primeira, a ordem topológica garante que os predecessores sejam processados antes dos sucessores.
Na segunda, a DFS calcula o maior caminho a partir de cada vértice e guarda o resultado para não recalcular.

Parte 2: numeração dos vértices

Objetivo:
Dar números de 1 até |V| para os vértices de modo que, se existe uma aresta (u, v), então u recebe número menor que v.

Fórmula da propriedade:

se (u, v) pertence a E, então f(u) < f(v)

Pseudocódigo:

Algoritmo NumerarVerticesDAG(G)
Entrada: um DAG G = (V, E)
Saída: função f que numera os vértices de 1 até |V|

início
    ordem <- OrdenaçãoTopologica(G)
    i <- 1

    para cada vértice v em ordem faça
        f[v] <- i
        i <- i + 1
    fim-para

    retorne f
fim

Algoritmo OrdenaçãoTopologica(G)
Entrada: um DAG G = (V, E)
Saída: uma ordem topológica dos vértices

início
    para cada v pertencente a V faça
        grauEntrada[v] <- quantidade de arestas que chegam em v
    fim-para

    fila <- todos os vértices com grauEntrada igual a 0
    ordem <- lista vazia

    enquanto fila não estiver vazia faça
        v <- desenfileire fila
        adicione v ao final de ordem

        para cada sucessor w de v faça
            grauEntrada[w] <- grauEntrada[w] - 1

            se grauEntrada[w] = 0 então
                enfileire w em fila
            fim-se
        fim-para
    fim-enquanto

    retorne ordem
fim

Justificativa:
Em um DAG sempre existe pelo menos uma fonte.
Ao remover uma fonte, os vértices que dependiam dela podem se tornar novas fontes.
Repetindo esse processo, obtemos uma ordem em que todo vértice aparece antes de seus sucessores.
Assim, se existe uma aresta (u, v), então u aparece antes de v na ordem e recebe um número menor.

Observação sobre a escrita do enunciado:
Se o professor escrever a condição usando a aresta (v, u), então a desigualdade aparece invertida:

se (v, u) pertence a E, então f(v) < f(u)

As duas formas dizem a mesma ideia: a origem da aresta vem antes do destino.

Conclusão:
Para um DAG, usamos ordenação topológica para numerar os vértices e também para calcular o maior caminho. O maior caminho pode ser encontrado por programação dinâmica em ordem topológica ou por DFS com memoização.
